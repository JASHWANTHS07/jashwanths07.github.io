PHASE 01 / PYTHON MASTERY
Beyond Scripts: Python as a Systems Language

Most engineers use Python. You will understand it. The interpreter, the GIL, memory layout, C extensions, async I/O, concurrent programming — all the way down to the metal.

File I/O & Storage Systems WK 1

Master Python's file system at OS level: mmap (memory-mapped files for zero-copy data loading), buffered vs unbuffered I/O, async file I/O with aiofiles, HDF5 (h5py) for ML datasets, Parquet/Arrow for columnar data, protocol buffers, and custom binary serialization with struct.

mmap: maps file → virtual address space (zero-copy) PagedIO: OS handles caching transparently struct.pack/unpack: C-level binary I/O HDF5: hierarchical, chunked, compressed datasets

Concurrency & Parallelism WK 2–3

Threading: GIL mechanics, thread-safe data structures, locks, RLocks, semaphores, thread pools. When threads help (I/O-bound) and when they hurt (CPU-bound).

Multiprocessing: fork vs spawn, shared memory (mp.Array, mp.Value), message passing, process pools — the right tool for CPU-bound ML preprocessing.

Asyncio: Event loop, coroutines, tasks, gather, async generators, async context managers. Essential for serving ML models at scale.

GIL: only 1 thread runs Python bytecode at once → Use multiprocessing for CPU-bound work → Use asyncio for I/O-bound work → Use C extensions (NumPy) to release the GIL

FlashAttention & Efficient Transformers WK 21–22

FlashAttention rewrote how attention is computed — tiling to avoid materializing the full N×N matrix, reducing memory I/O from O(N²) to O(N). Understand the math, then implement it in Triton. This is the single most impressive thing to show in a NVIDIA/ML systems interview.

Standard: write O(N²) attn matrix to HBM Flash: tile Q,K,V → compute in SRAM → no materialize Memory: O(N²) → O(N), 2–4× faster in practice Key insight: memory bandwidth, not FLOPs, is bottleneck
